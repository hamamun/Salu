The right-click layer — Player mode only

Five marks on the picture, opened by the right mouse button: shuffle · repeat · info · info · settings. Two concepts are built and live below — A · the second row (LOCKED 2026-09-19) and B · the ring (parked, kept here so the idea survives). Right-click the picture to try it. Esc closes, clicking outside closes, and a right-click always closes what is open first.

0 · The check first — may anything sit over the picture?

Asked before a line was designed. Answer, from Salu's own code:
Yes — over the video and over the album-art canvas. Both, today.
mpv is not a native child window here: media_kit paints each frame into a Flutter texture, so ordinary Flutter widgets draw on top of it. Salu already does exactly this.
  • The mpv canvas is a Flutter texture. video_screen.dart mounts media_kit's Video widget (texture renderer) and stacks Flutter children over it — LyricsOverlay, AlbumArtView — in one Stack.
  • Blurred glass over moving video already ships. The playlist, tracks and tune panels are BackdropFilter surfaces floating over the picture (panel width 322 px, top: kChromeBlockHeight). A frosted strip is the same material.
  • Audio is easier, not harder. The album-art canvas and the lyrics view are plain Flutter widgets — there is no engine surface in the way at all.
  • No engine caveats found. cc.md §5 / D20: media_kit re-registers its texture on every window resize only; overlays are untouched by that. Subtitles are drawn by mpv into the texture, so they stay under the menu, correctly.

3 · The marks carry the state — nothing else does

No labels, no text rows, no check marks, no shortcut letters (follow.md rules 1, 2, 6). The mark alone says what is on: full white + a very faint static glow for a live toggle, 55 % ink for off, and the bead for repeat-one.

Info · Settings
  • Suspended: shuffle keeps its state but drops to 55 % while repeat-one is active — exactly as the Playlist header already does.
  • Pitch, not boxes: 6 px inside a group, 14 px between the toggle pair and the door trio. Nothing is drawn around a group.
  • Hover: ink glides gray → white in ~120 ms, mark scales 1.06, chip names it after 600 ms. Press sinks to 0.90.
  • Never a sixth mark. If it needs nine items, it needs a different design.

4 · Both concepts, side by side — the owner picked A

Same marks, same order, same behaviour — only the way they arrive differs. A reads immediately and extends cleanly; B is more Salu and has no rectangle in it.

5 · What the layer is not

  • Never in Web mode. By construction, not by a rule: the player tree is not built while the browser owns the window, so the gesture cannot exist there.
  • Never in mini mode. The 32 px bar owes the viewer no popups — the mini shell builds none, and this is not the exception.
  • Remote's seat is empty. The strip's order keeps room for it between repeat and info, and draws nothing there — a control that leads nowhere does not exist.
  • Never the only door. Shuffle and repeat keep their home in the Playlist header, Settings keeps the title-bar mark, Info gets a second visible door. Nobody is told the shortcut exists — and nobody depends on it.
  • Never in channel mode for the toggles. Live lists drop repeat and shuffle (the channel header already has no pair), so the menu drops them too rather than offering two dead switches.
